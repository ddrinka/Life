# Agents

The shared conventions come from `.devcontainer/base/agents/AGENTS.md`, which is imported
ahead of this file. `.devcontainer/base` is a clone of
[ddrinka/DevContainer](https://github.com/ddrinka/DevContainer). This file holds only what
is specific to this repository. When a rule belongs to every repository, change it in that
clone and push from there. When a rule belongs only here, change it in this file.

## Project Context

Start at [README.md](README.md). Keep [TODO.md](TODO.md) and
[IMPLEMENTATION.md](IMPLEMENTATION.md) in sync as work proceeds. TODO.md is a
human-readable checklist. IMPLEMENTATION.md holds decisions, code references, and
commands.

## This repository

- This is the tooling. Personal data lives in a separate private state repository, and
  nothing personal is ever committed here. `fixture/` holds fictional data for tests.
- `src/life/templates/` is what a state repository is built from. `src/life/templates/GUIDE.md` and
  `src/life/templates/CLAUDE.md` are instructions to the agents that run inside a state
  repository, so a change there changes agent behaviour everywhere. Keep `GUIDE.md`
  under 150 lines; `life lint` enforces that limit in every state repository.
- The root `CLAUDE.md` is generated by the dev container and is not tracked. The
  tracked `src/life/templates/CLAUDE.md` is a different file for a different repository.
- To try changes against real data, clone a state repository into `state/`, which is
  ignored, and run `uv run life --root state <command>`.
- Run `uv run pytest -q` and `uv run life --root fixture --today 2026-09-08 lint` before
  reporting work done. Regenerate `fixture/MAP.md` with `life map` after any fixture
  change; lint fails when the map is out of date.
